# 기본 조명과 중앙 통과 기적 검증

## 변경

- 기본광과 추가광을 분리했다. 가로등의 따뜻한 기본 전구, 트리의 금빛 별과 작은 전구는 항상 켜져 있다. OFF는 추가광만 0인 상태다. 원본 사진을 검은색으로 덮던 레이어를 제거했다.
- 기존 네 패턴은 추가광만 제어한다. 추가광은 약 70ms 이내 켜지고 약 280ms에 걸쳐 기본광으로 돌아간다. 모션 감소 설정에서는 일정한 추가광을 쓴다.
- 가로등과 별은 공통 12방향 황금빛 스타버스트·흰 중심광·투명 헤일로를 사용한다. 사진의 가로등도 같은 Canvas 함수를 사용한다. 별의 PointLight와 가로등의 낮은 반사광 레이어는 주변을 약하게 밝힌다. 정적 건물 사진에 물리적인 3D 반사를 적용한 것은 아니다.
- 여섯 마을의 터널 내부 및 아치의 합성 점멸 조명을 모두 제거했다. 원본 PNG, 터널 가림 셰이더, 기차 전조등·차체는 유지했다.
- 기관차의 실제 카메라 투영 X좌표를 화면 중앙 0.5와 비교한다. 이전의 임의로 중앙을 보정한 X값은 사용하지 않는다. 보이는 전면 통과만 허용하고 한 바퀴당 중복을 막는다.
- 기존 기적의 세 사인파 진폭 합은 0.02255에 불과했다. 함수 호출 횟수만 확인하던 검사로는 실제 가청 출력을 보장하지 못했다. 새 기적은 5개 파이프 음과 합성 증기 노이즈로 짧은 0.42초 호출, 0.16초 숨 간격, 긴 2.07초 호출을 만든다. 총 길이는 약 2.65초다.
- 기적 동안 음악 버스는 28%, 주행음 버스는 38%로 덕킹한다. 끝나면 300ms 동안 복귀한다. 동작 OFF에서는 기적 소스를 중지하고 반주 덕킹도 해제한다. 사용자 음악 볼륨은 별도 GainNode에 유지된다.

## 검증

- `npm run build`: TypeScript, 기본 자동 테스트 34개, 웹 빌드, 웹 산출물 검사 통과. AIT/다운로드용 ZIP은 생성하지 않는다.
- 실제 Chromium의 `OfflineAudioContext` 48kHz 모노 출력과 클릭으로 활성화한 실시간 `AudioContext`에서 측정했다. 숫자는 정규화된 PCM이며 1.0이 디지털 풀스케일이다.

| 출력 | RMS | 피크 |
|---|---:|---:|
| 이전 기적 재현 | 0.00474 | 0.02279 |
| 기적 단독 | 0.12323 | 0.39080 |
| 주행음 단독 | 0.01146 | 0.06772 |
| 음악 단독, 볼륨 100% | 0.10133 | 0.36225 |
| 음악+주행음+기적, 덕킹 적용 | 0.12692 | 0.41819 |
| 동일 조합, 덕킹 미적용 비교 | 0.15993 | 0.64650 |

이전 기적은 주행음보다 약 **7.7dB 낮았으며**, 새 기적/주행음 RMS 차이는 **+20.63dB**다. 두 호출 구간은 각각 RMS 0.11738/0.14259이며 숨 간격과 종료 후 출력은 0이다. 모든 샘플은 유한하고 혼합 피크는 1.0 미만이다. 최종 리미터도 유지한다.

실시간 기적 버스 RMS 최고값은 약 0.1443, 최종 믹스 RMS는 약 0.1461이었다. 정지 후 재개 시 기적 RMS 0.1414, 마을 변경 후 0.1516으로 이벤트뿐 아니라 실제 신호도 확인했다. 기적 버스 GainNode가 0이거나 끊긴 경로가 아님을 확인했다.

- 실제 앱 화면에서도 사용자 클릭 후 자연 주행 약 22초 동안 기적 2회, 음악/주행음/기적의 동시 출력이 확인됐다. 기적 버스 최대 RMS 0.14452, 최종 믹스 RMS 0.14555/피크 0.38331, AudioContext 상태는 `running`이었다. 기적 발생 함수를 별도로 호출하지 않은 앱 통합 검사다.
- 430px 모바일 크기로 여섯 마을의 OFF/ON 화면 12장 및 1200px PNG 사진 12장을 생성·비교했다. 모두 기본 전구 opacity=1, OFF 추가광=0, ON 추가광=1이었다. 모든 ON 사진의 픽셀 밝기 합이 OFF보다 증가했다. 터널 점멸 요소는 없었다. 별 기본 emissive와 작은 전구 기본 emissive도 검사했다.
- 각 마을의 실제 Actors 카메라와 콜백을 3바퀴 검사했다. 여섯 마을 모두 보이는 중앙 통과 3회, 기준 투영과 최대 X좌표 오차 2.23e-16 미만이다. 숨겨진 통과, 동작 OFF, 정지·재개, 마을 변경은 별도 자동 검사한다.
- 실제 스피커 청감과 토스 WebView 기기 테스트는 이 클라우드 환경에서 수행하지 못했다. 측정은 브라우저의 오디오 그래프 및 디지털 출력 신호 검증이며 실제 기기 음색·체감 음량 평가는 별도다.

## 재현

저장소 루트에서 `npm run dev -- --port 5174 --strictPort`를 실행한다. Playwright와 Chromium이 설치된 환경에서 아래 명령으로 오디오 출력, 실제 앱 자연 주행, 여섯 마을 화면·PNG 및 카메라 판정을 검사한다. Playwright는 제품 의존성에 추가하지 않았다.

```sh
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs \
CHROMIUM_PATH=/usr/bin/chromium \
node scripts/check-browser.mjs
```

기본 결과 위치는 `/tmp/merry-validation`이며 `VALIDATION_URL`, `VALIDATION_DIR`로 서버와 결과 위치를 지정할 수 있다. 브라우저 오디오 검사는 `tests/browser/audio-output.ts`에 있다. 이 검사는 AIT 및 ZIP을 만들지 않으며, 유료 이용권이나 광고 보상을 조작하지 않는다. 특별 마을은 제품의 잠금 상태를 바꾸지 않고 독립된 렌더링 fixture에서 검사한다.
