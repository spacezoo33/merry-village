# PNG 촬영 검증 및 발견된 문제 수정

기준: 개발 브랜치 `feat/elliptical-train-ride`, SDK `@apps-in-toss/web-framework@3.9.0`. 프리미엄 이미지·모델·기차·음악·조명·눈 소스 및 광고 1회/7일 이용권 정책은 변경하지 않는다.

## 발견한 문제와 수정 범위

1. 움직임 줄이기 환경에서 베이직 화면의 마지막 전구 밝기는 0.5인데 사진은 약 0.2503이었다. 사진의 베이직 조명을 그릴 때 접근성 상태를 전달하지 않은 원인이다. `photo.ts`에서 촬영 시작 시 이 상태를 보관하고 사진 조명에 전달한다. 두 베이직 × 두 패턴에서 화면/사진 조명 일치를 실제 PNG 4장으로 재검증했다.
2. 화면의 중경 눈은 z-index 4로 액터(2)와 건축 조명(3) 앞에 있지만, 사진에서는 액터 뒤에 그렸다. 사진 합성에서 중경 눈을 액터·장식 조명 다음에 배치했다. 눈 크기·수·속도·색상과 화면 렌더링은 변경하지 않았다.

3. WebGL 미지원 환경에서 트리·기차 없이도 프리미엄 PNG가 생성되고 저장 버튼이 활성화되는 것을 재현했다. 사진 함수에서 프리미엄 액터가 없거나 스냅샷의 알파가 완전히 비어 있으면 출력을 거부한다. 이 경우 저장 버튼은 비활성 상태를 유지한다. WebGL을 끈 베이직은 2D로 촬영·다운로드가 계속 가능하다.

제작 장면이나 액터 렌더링 코드를 고치지 않고 사진 합성과 입력 검사만 수정했다. 사진은 UI가 아닌 배경/마을 이미지/실제 WebGL 스냅샷/조명/눈을 전용 캔버스에 합성한다. 1200×1560 PNG 유지.

## 실제 PNG 및 저장

모바일 에뮬레이션 Chromium(375×812, 터치, DPR 2)에서 사진 버튼과 실제 다운로드 버튼을 실행했다. 아래 9장 모두 PNG 헤더·해상도·MIME·파일 크기와 다운로드 완료를 확인했다. 출력 PNG는 모두 불투명하며 의도하지 않은 투명 배경/빈 캔버스 오류가 없다. 기본적인 어두운 터널·바닥 그림자 및 프리미엄 원본 배경 영역은 보존했다.

| 빌리지 | PNG 바이트 | 해상도 |
| --- | ---: | --- |
| 크리스마스 종탑집 | 3,175,389 | 1200×1560 |
| 눈사람 숲속집 | 3,120,379 | 1200×1560 |
| 포근한 크리스마스 | 3,415,916 | 1200×1560 |
| 눈꽃 숲속 마을 | 3,431,467 | 1200×1560 |
| 종소리 작은 성당 | 3,405,733 | 1200×1560 |
| 달빛 겨울 궁전 | 3,417,991 | 1200×1560 |
| 진저브레드 마을 | 3,417,415 | 1200×1560 |
| 오로라 호수 마을 | 3,403,982 | 1200×1560 |
| 별빛 천문대 | 3,379,766 | 1200×1560 |

- 두 베이직: 집·트리·장식·받침대·배경·눈·조명 포함. 기차는 없는 구성이다. 기존 외곽 마스크도 사진에 적용된다.
- 프리미엄 7종: 기관차와 객차가 보이는 앞쪽 주행 순간에 추가 촬영했다. 실제 촬영 이벤트/고정된 화면 포즈/사진에 사용된 스냅샷의 elapsed·treeAngle·trainAngle을 비교했다. 추가광을 제외한 불투명 액터 픽셀은 사진에서 99.80% 이상 일치하며, 나머지에는 눈 겹침 등 정상 합성이 포함된다. 열차의 위치를 사진용으로 바꾸지 않았다. 터널에 가려진 순간의 초기 촬영도 실제 가림 상태대로 나왔다.
- 화면의 조명 밝기 배열과 사진 캔버스의 추가광 밝기를 비교하고 중경·전경 눈이 액터 앞에 합성되는지 검사했다. 눈 품질 단계는 촬영 시 화면의 적응형 품질을 반영한다.
- 상단 조작 버튼·음악 플레이어·하단 메뉴는 합성하지 않으며, 9장 전체 구도와 PNG를 직접 확인했다. 지붕·받침대 및 액터의 새 잘림이나 누락은 발견하지 않았다.
- 실제 파일은 검증 환경의 `/tmp/merry-photo-final/`, 추가 접근성 검사는 `/tmp/merry-photo-reduced/`에 생성했다. 다운로드용 웹 ZIP이나 AIT는 만들지 않았다. PNG 바이트 수는 촬영 시점·포즈·조명·품질에 따라 달라진다.

## 자동화

`npm run build`: TypeScript, 기존 자동 테스트 47개, 웹 빌드, 산출물 검사 통과. 기존 프리미엄 핵심 에셋/소스 보존 SHA 검사를 유지한다.

`scripts/check-photo-failures.mjs`는 실제 WebGL 비활성 실행과 빈 스냅샷 모사에서 불완전한 프리미엄 PNG가 차단되는지 확인하고, WebGL 없는 베이직 생성·다운로드도 검증했다.

`scripts/check-photo.mjs`는 광고를 흉내 내는 운영 코드 없이 일회성 Playwright 컨텍스트에 저장 영수증 fixture만 주입한다. 기본 9종과 움직임 줄이기 4종의 PNG·조명·포즈·눈 레이어·다운로드를 검사한다. `PHOTO_IDS=cozy,forest,...` 또는 `PHOTO_IDS=none`으로 일부/접근성 검사만 실행할 수 있다. 사진 저장 자체는 실제 웹 다운로드 경로이며 실제 토스 광고 지급을 검증했다는 의미가 아니다.

## SDK / WebView 지원과 미검증 범위

- 설치된 공식 SDK의 `File.saveBase64({data,fileName,mimeType})`와 `isSupported()` 선언을 확인했다. 파일명에 `.png`, MIME에 `image/png`, `data`에는 Data URL 접두사를 뺀 Base64를 전달하는 기존 연결을 유지한다. 선언상 최소 토스 버전은 Android 5.218.0 / iOS 5.216.0이다.
- 브라우저에서는 Blob URL + `download` 링크로 저장한다. 모바일 에뮬레이션 Chromium에서 실제 다운로드 파일을 확인했다. 토스 WebView의 native API 호출 성공, 저장 위치/갤러리 노출, 사용자 권한 흐름은 토스 실기기에서 미검증이다.
- 설치된 SDK의 `Share.sendMessage`는 메시지, `Share.createLink`는 딥링크/OG 이미지 URL용이다. 이 선언에서 로컬 PNG 파일 직접 공유 API는 확인되지 않았다. 표준 Web Share API는 `navigator.canShare({files})` 지원과 사용자 동작을 확인해야 한다. 검증 Chromium에는 `navigator.share/canShare`가 없었다. 이미지 공유 버튼이나 검증되지 않은 공유 동작을 새로 추가하지 않았다.
- 공식 가이드 웹사이트는 현재 환경에서 CONNECT 403으로 차단되어 최신 웹 본문은 확인하지 못했다. 위 지원 범위는 실제 설치 SDK 3.9.0 타입 선언 기준이다. 토스 실기기 저장·파일 공유·저사양 성능·실제 청감은 이번 검증에서 확인하지 않았다.
