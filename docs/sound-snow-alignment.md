# 주행음·6바퀴 기적·눈가루·조명 위치 보정

이번 변경은 개발 브랜치의 기존 디자인·음악·조명 패턴·발광 강도를 유지한다.

## 소리

마스터 gain 0.9와 음악 버스 gain 1은 유지했다. 주행음 버스 gain은 1→0.75, 기적 버스는 1→0.70이다. 기존 주행음 생성 gain 0.75와 휘슬 합성 파형·2.65초 길이는 그대로다. 덕킹과 복귀도 새 버스 기준값을 사용하므로 기적 종료 후 이전 큰 음량으로 돌아가지 않는다.

실제 Chromium OfflineAudioContext에서 같은 파형을 기준 gain과 비교했다.

| 항목 | 수정 전 RMS | 수정 후 RMS | 배율 |
|---|---:|---:|---:|
| 주행음 | 0.01146154 | 0.00859615 | 0.75 |
| 기적 | 0.12323049 | 0.08626134 | 0.70 |
| 음악, 동일 볼륨 | 0.10133108 | 0.10133108 | 1.00 |

혼합 RMS는 0.09143, 피크 0.30605로 디지털 클리핑이 없었다. 실시간 기적 출력도 RMS 약 0.101로 확인했다. 이는 선형 신호 진폭 기준 감소다. 실제 스피커에서 느끼는 체감 음량 비율은 기기·청취 환경에 따라 다르며 이 환경에서 청감 검증하지 않았다.

## 6바퀴 기적

`Actors`의 기관차 실제 unwrapped 경로각으로 현재 바퀴 번호를 계산해 `TrainSound`에 전달한다. 6의 배수 바퀴에서 실제 투영 X좌표가 화면 중앙을 통과하고 터널 밖에 있을 때만 기적을 허용한다. 별도 타이머·랜덤 간격은 없다. 6번째 바퀴 중앙이 첫 허용 지점이며 이후 12·18번째 중앙 간격은 78초다.

빌리지 교체 시 이전 Actors의 정밀한 주행 진행도를 새 Actors 생성자에 넘긴다. 기적 중복 방지 바퀴 번호는 교체 시 초기화하지 않는다. 동작 OFF는 경로각을 진행시키지 않으며 ON에서 이어간다. 앱을 새로 시작하면 첫 바퀴부터 시작한다.

자동 테스트는 6개 마을 각각 1~18바퀴를 시뮬레이션해 기적이 정확히 `[6, 12, 18]`에서만 발생하고 간격이 78초임을 확인한다. 정지·재개, 같은 바퀴의 빌리지 교체와 중복, 터널 내부 통과도 검사한다.

## 눈

원근별 기존 크기에 0.55를 곱해 45% 축소했다. 화면과 PNG 사진이 같은 `snowSize` 함수를 사용한다. 기존 고품질 74개와 적응형 개수는 유지하며 앞·중간 레이어 낙하 시간을 늘리고 좌우 흔들림을 줄였다. 배경 흐림은 1px→0.35px로 줄여 큰 보케 대신 작은 눈가루가 보이도록 했다.

## 조명 좌표

원본 PNG는 수정하지 않았다. 각 빌리지의 원본 셀을 실제 브라우저 Canvas로 1024px까지 확대하고 기존 좌표를 겹쳐 가로등 중심을 대조했다. 최종 좌표는 `src/decor-lights.ts`에 셀 기준으로 저장한다. 상대좌표 변환은 위쪽 512px/아래쪽 505px 높이를 각각 사용한다.

| 마을 | 가로등 수 | 보정 내용 |
|---|---:|---|
| cozy | 7 | 오른쪽과 앞쪽 중심의 작은 오차 보정 |
| forest | 6 | 지붕 창문에 잘못 붙은 발광 제거 |
| chapel | 6 | 오른쪽 상단 중심을 x=443→462로 보정 |
| workshop | 6 | 오른쪽 상단·전면 중심 보정 |
| palace | 6 | 전면 좌우 오차 수정, 안쪽 가로등 2개 추가 |
| gingerbread | 6 | 오른쪽 상단·중간 및 하단 중심 보정 |

트리 별의 발광 중심은 ExtrudeGeometry 깊이 0.025의 중점에 맞췄다. 트리 회전 시 별과 발광의 월드 좌표가 일치한다. 작은 전구는 동일한 로컬 좌표를 공유하며 회전 중 실제 인스턴스 위치와 대조한다. 밝기·패턴·OFF 기본 불빛과 터널 조명 제거 상태는 유지한다.

## 재현 및 제한

`npm run build`는 기본 자동 테스트·TypeScript·웹 빌드·웹 결과물 검사를 실행한다. 브라우저 검사는 기존 `scripts/check-browser.mjs`를 확장했다. 6개 마을 × 320/375/430px × ON/OFF 화면과 PNG 사진, 회전 조명 중심, 주행 진행도 보존과 눈 토글을 검사한다.

```sh
npm run dev -- --port 5175 --strictPort
# 별도 터미널, Playwright/Chromium 설치 경로를 지정
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs CHROMIUM_PATH=/usr/bin/chromium \
VALIDATION_URL=http://127.0.0.1:5175 VALIDATION_DIR=/tmp/merry-nov5 \
node scripts/check-browser.mjs
```

특별 마을은 독립 fixture로 검사하며 광고 보상이나 이용권을 조작하지 않는다. 실제 토스 WebView 및 물리적 스피커 청감은 별도 기기 확인이 필요하다. AIT, 다운로드용 ZIP, main 병합은 수행하지 않는다.

이번 실행에서 기본 자동 테스트 35개, TypeScript 및 웹 빌드·산출물 검사가 통과했다. 여섯 마을의 320/375/430px ON/OFF 화면 36장, PNG 사진 12장, 별 및 전구의 회전 좌표 검사를 통과했다. 마지막 앱 UI 검사는 메뉴 썸네일을 제외한 `#scene-host` 선택자로 재실행하여 빌리지 변경 전후 진행도 유지, OFF 진행도 정지, ON 재개, 눈 ON/OFF 및 이전 마을 조명 제거를 확인했다. 실제 촬영 UI에서도 눈이 포함된 1200×1560 PNG 생성을 확인했다. UI 부분만 재실행할 때는 `VALIDATION_SCOPE=app`을 지정할 수 있다.
