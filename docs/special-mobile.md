# 모바일 특별 빌리지 통합

## 구성

기본 마을 3종은 유지하고, 특별 마을은 달빛 겨울 궁전·진저브레드 마을·오로라 호수 마을·별빛 천문대 4종으로 변경했다. 이전 산타 공방의 원본 에셋과 레이아웃은 삭제하지 않고 역사 자료로 보존한다. 오래된 선택 ID는 기본 마을로 안전하게 돌아온다.

새 특별 마을은 기존 제품 사진형 스타일을 참고해 이미지 생성 도구로 새로 제작했다. 외부 사이트의 이미지·녹음물을 다운로드하지 않았다. 원본 생성물은 작업 공간 `/workspace/generated_images/exec-a68c63ca-0e77-4745-a753-0b56ae6d64c2.png`이며 SHA-256은 `005bd44a7a0536fe56cc766add38244be65c2fe11e156b4e0b824bc48931e31a`이다. 참조는 저장소의 기존 `product-villages.png`였다. 4분할 생성물을 각 마을로 분리하고 WebP로 최적화했다. 새로운 외부 상업 음악·현대 편곡은 사용하지 않았다.

| 특별 마을 | 실제 장면 구성 | 패턴에 참여하는 외부 광원 |
|---|---|---:|
| 달빛 겨울 궁전 | 푸른 지붕·금색 첨탑·계단·정원·분수·금빛 사슴 | 18 |
| 진저브레드 마을 | 과자 건물·아이싱·사탕 지팡이·선물·눈사람 | 20 |
| 오로라 호수 마을 | 얼음 전망대·호수·다리·백조·크리스털 | 18 |
| 별빛 천문대 | 돔과 망원경·별빛 아치·정적 회전목마·정원 | 17 |

건물·분수·회전목마 등은 정적인 제품형 2.5D 플레이트다. 회전하는 트리와 실제 연결 열차는 기존 Three.js 모델을 재사용한다. 궁전의 트리는 분수를 가리지 않도록 옆으로 배치했고, 각 마을마다 트리 기준점·크기·선로·터널 입구를 별도로 맞췄다. 오로라 호수의 배경에는 기존의 가벼운 CSS 오로라를 적용하며 모션 감소·화면 비활성화에 대응한다.

## 조명·기차·눈

- 가로등·별·장식등은 원본 셀 627px의 개별 중심 좌표를 512 기준 상대좌표로 변환한다. 창문은 패턴 대상이 아니다. 4가지 패턴과 기본광/추가광 정의는 유지한다.
- 작은 장식과 큰 별/조형물의 추가광 크기·강도를 달리하며 DOM과 PNG 사진은 같은 광원 데이터와 Canvas 함수를 사용한다. 터널 내부 광원은 없다.
- 트리 별과 전구는 회전 모델에 붙어 움직인다. 기존 기본 마을의 캘리브레이션은 유지한다.
- 기관차 1대·객차 2대, 13초 순환, 터널 가림, 6/12/18바퀴 중앙 통과 기적과 낮춘 두 효과음 버스 gain은 유지한다.
- 작은 눈가루 크기는 바꾸지 않고 고품질 개수를 74→111로 50% 증가시켰다. 중간 84개·낮음 66개로 적응하며, 선택창에는 눈을 표시하지 않는다.

## 음악 및 이용권

선택한 곡은 기본적으로 같은 곡을 계속 반복한다. 예전 반복 OFF 저장값도 ON으로 마이그레이션한다. 이전/다음은 5곡을 양방향 순환하고 빌리지 변경은 곡을 바꾸지 않는다. 곡이 끝났다는 콜백으로 다음 곡을 고르지 않는다. 음악 원선율·음량·합성은 유지한다.

빌리지 이용권은 `villagePasses[villageId]`로 각각 관리하며, 특별한 밤 3종은 기존 `pass`에 별도로 보관한다. 활성 이용권은 연장하지 않는다. 만료된 마을은 잠기고 기본 마을로 돌아가며, 밤 이용권과 다른 마을 이용권에는 영향을 주지 않는다. 기존 전체 이용권을 새 4종 이용권으로 임의 복제하지 않는다.

보상은 SDK의 `userEarnedReward`와 정상 종료 확인을 거친 `earnPass` 결과가 참인 경우에만 요청한 대상에 지급한다. 광고 요청 중 대상 전환을 막고 시작 시 대상을 고정한다. 로딩 실패·취소·시간 초과·보상 미확인에는 지급하지 않는다. 웹·개발 도구에서는 지급하지 않는다. 잠금 마을을 눌렀을 때는 저장된 실제 선택을 바꾸지 않는 미리보기이며 상태와 광고 이용 버튼을 표시한다. 미리보기 사진 저장은 허용하지 않는다.

이용권은 기존처럼 이 기기의 로컬 기록이며 서버 검증 영수증은 아니다. 저장소 삭제·기기 변경 시 복구를 보장하지 않는다.

## 모바일·성능

- 320~430px 세로 화면, 짧은 640px부터 큰 932px 높이에서 전체 마을을 담도록 가용 화면 높이에 따라 장면 폭을 조절한다. 가로 스크롤을 막고 44px 이상 주요 터치 영역을 제공한다.
- 빌리지 카드 1열·세로 스크롤·큰 정적 썸네일·잠금과 만료 표시를 사용한다. 썸네일에는 실제 트리/기차를 합성하고 눈과 조작 버튼은 넣지 않는다.
- SDK 3.9.0 `SafeArea.get/subscribe`와 브라우저 CSS `env(safe-area-inset-*)`를 함께 사용한다. 실제 토스 내비게이션과 인셋 값은 기기 테스트가 필요하다.
- 선택창 뒤의 3D 렌더링·기차 음향·눈은 일시정지하고 음악은 계속 재생한다. 닫으면 같은 주행 진행도에서 재개한다. 광고 중·앱 비활성화 시에는 기존처럼 음악도 정지한다.
- 고품질에서는 60fps를 목표로 RAF를 사용하고 프레임 압력으로 효과 품질이 내려가면 렌더링 간격도 줄인다. 소프트웨어 Chromium 검증은 모바일 GPU의 60fps 보장이 아니다.
- 7개 전체 이미지 중 선택한 한 장만 표시하고, 카드는 별도의 384px WebP 썸네일을 지연 로딩한다. 전체 특별 이미지 627px·136~143KB, 썸네일 약 42~47KB다. 트리 가지 텍스처는 512px/102KB, 배경은 약 97KB WebP로 변환했다. 원본 PNG는 모두 남긴다.
- 사진용 이미지 캐시는 배경과 선택한 마을만 유지하며, 장면 교체 시 기존 3D 자원을 정리한다. 사진 출력은 기존 1200×1560 PNG다.
- 최종 웹 산출물은 약 2,165,000바이트(약 2.17MB), 이전 8,045,779바이트 대비 약 73% 감소했다. 기존 약 650KB 메인 JS 청크 경고는 남아 있으며 분할을 위해 관련 없는 대규모 리팩터링은 하지 않았다.

## 검증 및 실행

`npm run build`: TypeScript·자동 테스트 38개·웹 빌드·산출물 검사 통과. 7개 마을의 3가지 폭별 광원 중심·회전·ON/OFF·경로·사진, 기적 1~18바퀴, 음악 기본 반복, 독립 이용권·실패·만료·누적 방지와 기존 밤 효과를 검사했다.

```sh
# 개발 서버 / 장면·광원·사진 검사
npm run dev -- --port 5177 --strictPort
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs CHROMIUM_PATH=/usr/bin/chromium \
VALIDATION_URL=http://127.0.0.1:5177 node scripts/check-browser.mjs
# 실제 산출물에서 모바일 UI·잠금·음악·눈 검사
npm run preview -- --port 4177 --strictPort
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs CHROMIUM_PATH=/usr/bin/chromium \
VALIDATION_URL=http://127.0.0.1:4177 node scripts/check-mobile.mjs
```

## 실제 토스 앱에서 필요한 확인

`public/runtime-config.json`의 `rewardedAdGroupId`가 비어 있어 실광고를 재생하거나 실제 이용권을 지급하지 않았다. 유효한 보상형 광고 그룹 ID 설정 후 실제 토스 앱에서 4개 마을별 획득/취소/실패/만료, 밤 이용권과 분리, 네이티브 PNG 저장을 확인해야 한다. 광고 그룹 ID는 공개 설정이며 비밀키를 넣으면 안 된다.

공식 개발 문서 사이트는 현재 HTTPS 프록시에서 403으로 차단되어 사이트 내용을 읽었다고 주장하지 않는다. 설치된 공식 SDK 3.9.0의 타입·API·기존 연동을 기준으로 구현했다. 실제 WebView 안전 영역·저사양 기기 프레임률·물리적 스피커 청감·실광고 지급은 미검증이다. 웹에서 보상 완료를 조작해 보여주지 않았다. AIT·다운로드 ZIP·main 병합·앱 식별자 변경은 하지 않는다.

최종 프로덕션 검사에서 320×640·375×812·430×932·430×640의 주요 버튼 44px·가로 스크롤 없음·7개 단일 열 카드·4개 잠금 미리보기·곡 순환/반복·111개 눈·기존 밤 효과가 통과했고 콘솔 예외는 없었다. 상단 44px·하단 20px 안전 영역을 CSS로 모사한 320×640·430×640·375×812에서도 장면과 하단 메뉴가 화면 안에 들어왔다. 이는 실제 토스 기기 검증을 대체하지 않는다.

프로덕션 첫 화면에서 로딩된 이미지 요청은 배경 97,406바이트·선택한 cozy 111,646바이트·트리 텍스처 101,592바이트(합계 310,644바이트)였으며 다른 전체 마을 이미지는 요청하지 않았다. 메뉴를 연 동안 주행 진행도가 멈추고 음악이 계속 재생되는 것을 확인했다. PNG 생성 및 실제 브라우저 다운로드도 1200×1560으로 통과했다.
